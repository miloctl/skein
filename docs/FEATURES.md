# Skein — feature reference

Everything shipped, grouped by area. Every feature has a deterministic,
keyless core; rows marked **LLM-upgradable** get better with a model provider
but never require one. All writes flow through `backend/app/services/` from
both write paths (human REST, agent tools) and carry provenance
(`origin`, `created_by`) plus an activity-log entry.

**Navigation (since 2026-07-26):** five top-level destinations — My Day ·
Chat · **Work** (Plan the week `/planning` · Health `/portfolio` · Browse
`/dashboard` · Insights `/insights` · Reports `/artifacts`) · **Inbox**
(Approvals `/review` · Requests `/intake` · Paste
notes `/ingest`) · **Team** (Agents `/agents` · 1:1s `/people` · Charter
`/charter` · Activity `/activity`). All URLs are unchanged; the groups are
tabs. Below the `sm` breakpoint the header gives its width to the search
field: the identity chip shows the avatar alone and carries the name as
screen-reader text, and the section tabs wrap. At 360px the row holds 328px
of content box, and the four things in it (logo, search field, identity chip,
capture button) do not all fit at their desktop sizes — the name at 7rem left
the search field 10px wide. `e2e/responsive.spec.ts` walks every page at
360px and fails on any sideways overflow. Manager-grade
controls (request triage, exec readout, authority editing, promise
verdicts) sit behind a per-browser "manager controls" toggle so developers
never carry the manager cockpit by default. The toggle is scope control, not
authorization: the endpoints behind it are ordinary `CurrentUser` writes and
stay reachable by anyone who can reach the API — only authority editing requires an
administrator (AdminUser).

## Work tracking

| Feature | How | Surface |
|---|---|---|
| Milestones & tasks | statuses, priorities, due dates, assignees | `GET/POST/PATCH /api/milestones`, `/api/tasks` · dashboard · tools |
| Questions & answers | assignment + notification to assignee | `/api/questions`, `/api/questions/{id}/answer` |
| Decisions with half-life | `review_by` date; daily sweep flips overdue ones to `stale`; supersede chains (`superseded_by`) instead of contradicting; reconfirm to reset; `category=charter` marks team-charter/decision-rights entries (review_by required, category survives supersession). A **risk register** needs no new feature: a risk IS a decision (`risk: <what> — mitigation: <how>`) with an owner and a `review_by`, riding the same stale sweep | `POST /api/decisions` (accepts `review_by`, `category`), `/api/decisions/{id}/supersede`, `/{id}/reconfirm`, `GET /api/decisions?status=&category=` · `/charter` page |
| Waiting-on edges | a task records what it's stuck behind (`waiting_on: task:12 \| blocker:3 \| promise:7`, `-` clears) — surfaced as health receipts and slip-forecast annotations; satisfied targets (done/resolved/kept) stop counting automatically. Deliberately not Gantt. **The edge reads BOTH ways**: the task peek names what finishing this one releases, `skein pr-body` puts that list in the pull request, and Work → Plan the week names the open task that releases the most. ONE edge counts as released work: a task waiting on this task. A `blocker:` edge deliberately does not, because `blockers.task_id` names the task a blocker BLOCKS rather than one that causes it — counting through it claimed a task released work while the same blocker was what stopped that task from finishing. A `promise:` edge is settled by a promise verdict, never by finishing a task. The walk is viewer-scoped at every hop (a task nobody may read is not countable through the chain), closes cycles on a visited set, and stops at ten hops and says so rather than reporting a number that quietly stopped counting. Until this existed, typing an edge cost the person who typed it and paid them nothing, which is how edges rot | `PATCH /api/tasks/{id}` · agent tool `update_task` |
| `/ask` with receipts | the nav box's `?` prefix. NOT a model call: the same FTS index, retried on the separate words when the phrase matches nothing, returned as snippets citing `entity #id` and marked as loose. Function words are dropped from the retry, or `the` alone matches most rows. Hybrid with semantic hits when embeddings are on | `GET /api/ask?q=` |
| Growth interests | self-declared per person (🌱 on My Day); shown in what-if staffing projections so growth fit is visible when staffing — display-only, no matching, no scores; overwrites logged old→new | `GET/POST /api/users/growth-interests` (prefilled; empty save clears) |
| Standups | blocker text auto-files a real blocker | `POST /api/standups` · CLI `skein standup` |
| @mentions | `@name` in a task (title or description), note, question, answer, or decision notifies the named person (immediate tier) — deterministic parse against the roster at write time, in the service layer, so every write path carries it with no new tool or gate row; `mention_log` dedupes by (entity, id, person), so an edit or typo fix never notifies twice; self-mentions and the question assignee (already pinged by assignment) are skipped; a name with a space cannot be one `@token` and is not mentionable. Agents are mentionable ON PURPOSE — an agent identity reads its notifications through `my_agent_inbox`, so `@scout take this one` reaches scout the way it reaches a person. **In chat** a mention is delivered the same way, by the row the turn FILES: a chat thread is owner-scoped, so there is no row for a notification to point at and nothing is invented to make one. A turn that files nothing and names a teammate says who it did not reach and how to reach them (`turn_guard.unnotified` — deterministic, roster lookup, no model), and the Chief of Staff is told to route an `@name` into an `ask_question` or `create_task` carrying that name, asking first because "I spoke to @mira yesterday" is not a request. Keyless, `MockAgent` captures the message, so the note carries the name and the mention lands for real | `services/mentions.py` · rides the prose write paths |
| **Task side peek** | `?task=<id>` opens a panel over whatever page the reader is on — the one landing place for every task reference (My Day tasks and due-soon, Browse, Recently shipped, search hits, planning carryover). Shows status, priority, assignee, due date, the finish date once it is done, week, milestone, engagement, waiting-on, **the open blockers filed against it** (owner, impact, escalation — a blocker is what SETS status `blocked`, so a panel showing the state without naming its cause sent the reader to the register by hand), what finishing it unblocks, delegation, visibility, the forge link, and the worklog; delegation is a control inside it. Back closes it (a real history entry, not private state); Escape closes it; the background is `inert` while it is open, because `aria-modal` prunes the screen reader buffer and leaves Tab order alone. The joined milestone and engagement names take their OWN scope filters on the nullable side of the join, so a private parent's title never rides a readable task | `components/task-peek.tsx` · `GET /api/tasks/{id}` |
| **Nav search + ask** | One input, two backends: plain text runs `GET /api/search`, a leading `?` runs `GET /api/ask` (a widened retry, not prose — the placeholder does not advertise it, because with embeddings on both return the same rows for an ordinary question; the field guide card teaches it). FTS5 wraps matches in `<b>`, and the snippet is built from every row anyone has written — so the tags are parsed into text runs and emphasized by React, never rendered as HTML. Task hits open the peek, decision and lesson hits land on their own row by anchor. Hidden for an anonymous visitor: every result is viewer-scoped, and an unnamed caller would read an empty index as "the team has nothing" | `components/nav-search.tsx` |
| Calendar | events, today's shown in My Day | `/api/events` |
| Quick capture | rule-based routing: `q:`→question, `todo:`→task, `blocked …`→blocker, `decision:`→decision, `promised:`→promise, `awaiting:`/`waiting for:`→a promise made TO the team, `req:`→intake request, `fb: <person> — …`→author-private feedback journal (strong identity required, single-line only, refused in chat), else note. The ⌘K palette affords the grammar: prefix chips + a live "will file as: …" preview mirroring the backend rules | ⌘K palette · `POST /api/capture` · CLI `skein capture` · Slack `/skein` · MCP `capture` |
| Meeting-notes ingestion | paste raw notes; deterministic per-line capture-grammar pass; every hit becomes a review-queue **proposal** (never a direct write); `fb:` lines flagged and skipped; unclassified lines returned for a human skim; batch-approve in `/review` | `/ingest` page · `POST /api/ingest` |
| Full-text search | FTS5 over every entity, reachable from the nav search box; short-id fast path: `#42` / `task 42` / `blocker 3` jump straight to the row in search and `/ask` (bare `#N` means task, the meaning git trailers already give it); optional embeddings (`SKEIN_EMBEDDINGS=1`; provider via `SKEIN_EMBED_PROVIDER` — openai, openai_compatible, or keyless ollama; backfill existing records with `python -m app.backfill_embeddings`) | `GET /api/search?q=` · CLI `skein search` |
| My Day briefing | attention items grouped by judgment type (Decide/Unblock/Promise/Review/Notice), each with a "why you're seeing this" reason. Every item also carries an **audience**: `you` when a column names the reader (assigned, owned, authored, notified) and `team` for a shared queue anyone may work — the two render in separate cards, because "Needs you" over the team's intake queue and every pending proposal is what teaches a reader to discount the page. A promise, a stale decision and a proposal are personal only when `created_by` / `decided_by` / `requested_by` is the reader, the same filters `rituals.week_open` uses for the same sentences. `GET /api/attention` returns **two numbers**: `inbox` for the nav badge (proposals + triage, what that page shows) and `yours` for the tab title and `skein attention`, which both say "waiting on you" — and `yours` must equal the briefing's `attention_total`, held together by `test_attention_count_matches_the_page`, or the tab reads twelve over a page saying nothing waits. The task list leads with **urgent or overdue**, then this week's commitment (chipped `this week`), then work already in progress: a plan capped at five per person otherwise buries the row that says the plan changed | `GET /api/briefing` · `GET /api/attention` · CLI `skein my-day` |
| People (private) | per-report 1:1 prep: deterministic "since last time" brief from team-visible data + author-private notes/feedback journal in a separate `private.db` (0600) that backup/export/FTS/MCP/agents structurally never open; read-time-only feedback-gap nudge; author-only delete with tombstone; author-scoped audit trail (adds/reads/briefs/deletes); strong identity (personal key) required — X-User is 403 | `/people` page · `/api/private/*` |
| Authority half-life | `autonomous`/`notify` grants expire to a findings nudge after 90 days (reconfirm = re-grant); `forbidden`/`review` never expire. "Nothing in Skein is trusted forever — not decisions, not agents" | `POST /api/agents/authority` · `authority_stale` rule |
| Crews | Durable named groups of people, the membership the visibility tier reads (`docs/VISIBILITY.md`) — removing someone takes away their access to every crew-tier row they did not write. Whoever creates a crew becomes its **steward** — the person who adds and removes members — and a crew can never reach zero stewards from either side (removal and self-demotion both refuse). Editing needs strong identity plus stewardship of that crew, or an administrator named in `SKEIN_ADMINS`. Not the scarcity fallback that makes every key holder an administrator in a default trusted-header deployment — with it, any of them made themselves steward and evicted the one who was there, on a boundary that is about to decide what a person reads. An agent identity cannot join: agents read through the gated tool surface with its own authority matrix. Names fold in Python the way roster names do, so `Café` and `CAFÉ` are one crew, and the four system-actor names are refused. A crew is **deactivated**, never deleted (the roster's word, for the roster's reversible shape) — `crews_of` keeps returning a deactivated crew so rows already scoped to it stay readable, while `assert_writable` refuses new ones. Removal takes the person in the body, not the path: a roster name can hold `/`, which no URL path segment matches | `/settings` Crews card · `GET/POST /api/crews` · `POST /api/crews/{id}/members` · `services/crews.py` |
| Visibility tiers | Every content row carries `private` / `crew` / `workspace` (`004_visibility_tier.sql`, 16 tables). `workspace` is the default and is exactly how every row behaved before the column landed, so the migration changes nothing anyone can see. **`crew` is filtered at read time** — `services/scope.py::visible_filter` returns an AND fragment spliced into each scoped read, and it takes the TABLE, never a column, because four tables carry both their real author column and a `created_by` holding the agent slug (on that one, a private note hides from the person who wrote it). **`private` is not filtered, it is excluded** — no FTS row, no embedding, no context pack, digest, readout, finding, calendar event, admin export row, and no body in `activity.detail` (`scope.detail`, because the ledger is hash-chained and a body written there has no undo). Jobs and egress builders have no viewer — "who is this digest for" has no answer — so they read `scope.WORKSPACE_ONLY` and nothing else. The handoff is generated by a person, so it takes a viewer and narrows the body to the artifact's own tier (`scope.audience`). Reading a scoped row needs STRONG identity: in trusted-header mode a name is whatever the caller typed, so `Viewer` carries the strength in the type rather than leaving the rule at every call site. A refusal is 404, never 403, and the absent row and the unreadable row raise the same sentence (`scope.missing`) — any other wording answers "does #12 exist" for sequential integer ids. Writing a scoped row needs crew membership, checked inside the write's own transaction. Handing one to somebody who cannot read it is refused at the write (`assert_readable_by`, with the author exempted — without that, every private capture that classified as a blocker was refused). Changing one you cannot read is a 404 (`assert_editable`, which lets a machine actor work a crew row because the forge webhook and the review-apply path ARE the mechanism, but never a private one). `scope.UNSCOPED` gives every unscoped table a written reason (pinned by `test_every_unscoped_reason_is_written`) and `scope.CLASSIFIED` maps every scoped one to its author column, and three CI tests walk `sqlite_master` and the service AST: any table in neither map, any id-addressed mutation with no guard, and any read of a scoped table with no viewer, no `WORKSPACE_ONLY` and no written excuse | ⌘K palette · standup card · `VisibilityPicker`/`VisibilityBadge` · `services/scope.py` · `tests/test_visibility_{writes,authz}.py` |
| Per-crew context packs | The team pack plus one section of that crew's own rows — decisions, conventions, open questions, open work. The shared body stays a prefix, so a reader can tell which half the whole roster has. Each crew versions independently (a shared counter would bump every crew whenever any one published), and the crew id is in the artifact filename as well as the row. Reading and publishing both need membership, resolved from the viewer so a self-asserted name is not a door; publishing also needs the crew to be active | `GET /api/context-pack?crew=` · `POST /api/context-pack/publish` · `services/context_pack.py` |
| Identity walls | One name, one identity, asked the same way everywhere. `services/users.py::is_agent` folds in PYTHON (NFKC, strip category Cf, casefold) — sqlite's `lower()` is ASCII-only, so a SQL-folded wall read `SCOÜT` and `scoüt` as different names while `resolve_teammate` read them as one. Agent identities are refused on REST at every door AND at the perimeter, because the perimeter runs before any handler and the file-backed catalog reads never reach `routes/deps.py` at all. The four system-actor names (`system`, `scheduler`, `team`, `forge`) are refused for every kind, at creation, at rename, and at each credential door: the activity feed shows a system actor's rows to EVERY viewer, so holding one walks your own writes past the anti-surveillance rule. `refuse_fold_collision` refuses ANY row that folds onto an existing name, same kind included, so `Scout` the human never lands beside `scout` the agent and a second `SCOUT` agent never lands beside the first — authority and trust key on the exact name, so a fold-variant agent row answers to nobody's kill switch. A roster row that predates a wall is named in the boot log, never auto-renamed: moving a person is `rename_user`, which knows all 47 attribution columns and the private notes DB that SQL cannot reach. Operator config never aborts boot — a name it cannot reserve is a logged error, the way a bad model provider degrades to mock | `services/users.py` · `routes/deps.py` · `main.py` perimeter |
| Rate caps | per-user sliding window on flood-prone writes: capture 30/min (REST, chat, and MCP), ingest 6/min, key requests 3/min, and task delegation, question assignment and the chat thread and folder writes on the shared `write`/`delete` buckets — question assignment because it NOTIFIES the assignee, so it is a send rather than an edit. The `/api/private/*` writes take a bucket of their OWN: that store is excluded from backup, export, FTS and every agent surface, so nothing else would notice a flood, and sharing the write budget would lock a person out of their 1:1 notes during a busy planning hour. Which routes may go uncapped is a TEST, not a habit: `tests/test_bounded_routes.py` walks the route table and fails any mutating route that neither calls the check nor carries an EXEMPT row with a reason, and fails an EXEMPT row that stopped being true. A DoS-annoyance guard, not a security control. A spent cap answers **429** with a `Retry-After` computed from the window, never a bare 400, so a client can tell throttling from a malformed body and knows when to retry. The `write` bucket keys on the (agent, requester) PAIR, so the shared default chat identity is not one team-wide budget | `app/ratelimit.py` |
| Deployment tuning | administrator-set runtime limits held in `app_settings`, overriding the env default and clearing back to it: chat/write/capture caps, the flock member deadline, the model socket timeout, and both thread-pool sizes. Every knob carries an inclusive floor and ceiling (a 0 cap refuses everyone; a 1-thread pool deadlocks), reports whether it is live or needs a restart, and is activity-logged. Cross-knob invariants are refused at write time — the socket timeout can never be set at or below the member deadline, which is the ordering that keeps a cold model load from dying as a failed member. Values are read through per call, never cached, so the numbers stay correct if a second worker ever exists. **Identity settings are deliberately absent** (auth mode, proxy hops, administrators, provider credentials): an administrator who could lower that bar could let themselves through it, so those stay env-only. `AdminUser` for the read too — the remaining headroom is reconnaissance | `GET/POST /api/settings/tuning` · `services/tuning.py` |
| ICS calendar feed | events + milestone/promise due dates; dedicated `SKEIN_ICS_TOKEN` (never the API token); fail-closed when the API is token-locked | `GET /api/calendar.ics` |
| First-run onboarding | checklist computed from real state, personal steps (name, capture, standup, key) separated from team facts (engagement, teammate); dismissible card on My Day (restorable from Settings); anonymous visitors get a single "Who are you?" gate | `GET /api/onboarding` |
| Field guide ("knots") | first-use feature discovery: 35 cards from `backend/fieldguide/knots.yaml`, tied/untied per person, untied cards carry the how-to + deep link; state is SELF-visible only (anti-surveillance rule — no per-person grid, no unlock feed, no activity rows); silent retroactive seeding from existing data; one weekly rotating My Day suggestion (dismiss = permanent); builders' signal is the `feature_unadopted` findings rule (zero-adoption, nameless). Spec + non-negotiables: docs/FIELD-GUIDE.md | `/guide` page · 👤 identity menu (top bar: Settings · Field guide + tied count · identity-strength line — replaces the separate gear button; renaming lives in Settings only) · `GET /api/field-guide` · `/hint` · `POST /api/field-guide/dismiss` (rate-capped) |
| Key self-request | "Request a key" on Settings/1:1s files a team-visible nudge with the exact mint command (idempotent while unread) — the operator ceremony stays, finding the operator doesn't | `POST /api/keys/request` |
| **Activity feed** | Team → Activity: one sentence per provenance-ledger row — "{actor} {verb}" from a registry beside the ledger it names. A row whose ACTION is task-shaped carries a link into the task peek from its expanded panel — keyed on the action and never on the detail, because a bare `#N` is a blocker id or an API-key id just as often, and the entity word lives in the sentence the registry builds, with an honest generic row for any unregistered action (never a fabricated verb). Salience tracks consequence: destructive and security-relevant actions are loud, writes normal, system bookkeeping quiet. **Scope is the anti-surveillance rule made structural**, enforced in the service: agent and system actors plus your OWN rows — another human's rows never appear and no parameter exists to request them. Raw-rows toggle (same truth, zoom level), click-to-expand per row, seq as the cursor (monotonic and gap-free by construction; rows that predate the chain stay on the raw endpoint, which carries the SAME scope — as does My Day's since-yesterday digest, or either would be the one-curl bypass of the rule). A rename never rewrites the ledger: every chained digest covers its actor, so history stays under the old name | `/activity` page · `GET /api/activity/feed` · `services/activity.py::feed` |
| Agent status strip | three states in plain words on Team → Agents: live model, mock ("deterministic mode"), or misconfigured (red dot + the reason from `provider_error`) — plus review-gate state | `GET /api/agents/status` |
| Derived standup "yesterday" | the My Day composer prefills yesterday from the user's own activity log — asked-for input becomes derived | `GET /api/briefing` (`your_work.standup_suggestion`) |
| Themes | 7-pack theme gallery (Loom/Ledger/Phosphor/Atelier/Claw/Hermes/High-contrast) — packs re-weave type, radii, shadows, textures, selvage, and empty-state voice, not just colors; colorway accents + custom two-hue dials (AA at every hue, enforced by `scripts/check_theme_contrast.py` in `lint.sh`: it reads the packs out of `globals.css`, so a new pack is covered on the day it ships, and it holds every colorway thread to 5.5:1 on every pack surface). **`frontend/lib/theme.ts` is the single source** for the pack and colorway ids, the storage keys and the custom-hue formulas: `layout.tsx` GENERATES its pre-paint script from them (`lib/theme-boot.ts`) instead of repeating them, and the contrast checker PARSES them instead of copying them — then fails if `theme.ts` and `globals.css` disagree about which packs exist. Each formula row declares what it must stay legible against, so the sweep covers ink on every pack surface (floor 5.56:1) and solid fills under white text (floor 5.27:1); theme (incl. custom hues) auto-saves to the profile and follows the person to any browser; shareable theme code (copy/paste JSON under Customize & share); operator-set team default adopted by fresh browsers and anonymous visitors (AdminUser, a default never an override) | Settings · `frontend/lib/theme.ts` · `GET/POST /api/users/theme` · `POST /api/users/theme/default` |
| Availability ledger | PTO/on-call/focus windows (absences table): capacity marks people away, the weekly draft skips anyone away 3+ weekdays (listed as skipped, never silently), what-if staffing shows upcoming PTO; manage on Work → Browse Time-away card | `GET/POST/DELETE /api/absences` · tools `add_absence`/`list_absences` (agent create is ALWAYS a proposal) · CLI `skein absences add/list/rm` |
| Delegation work loop | claim → report_progress (worklog) → submit_for_acceptance: acceptance is ALWAYS a proposal bound to the sponsor (others need a reason on record; only key-authenticated sponsor verdicts feed trust); worklog readable pre-verdict | tools `claim_delegated_task`/`report_progress`/`submit_for_acceptance` · `GET /api/tasks/{id}/worklog` · CLI `skein worklog`/`skein inbox` |
| Authority review job | weekly scan turns strong-verdict streaks into FILED proposals: 5 straight key-authenticated sponsor/reviewer approvals at review → propose notify; 3 straight rejections likewise → propose demotion to review (weak-header and override verdicts never count); agents can never approve, so no self-promotion | job `authority-review` · registry entity `authority` |
| Week rituals | Monday brief (each person's own promises, stale decisions, questions, due tasks → personal notification + artifact) and Friday close-out (due promises, stuck-closing engagements, stale proposals, open questions → team notification + artifact); scheduler-run weekly, manual buttons under manager controls on Work → Health. The REST routes no longer force: `force=true` is a separate, explicit ask, because forcing walks past the weekly claim and re-briefs the whole roster with the same personal notifications on every click | jobs `week-open`/`week-close` · `POST /api/rituals/week-open|week-close` |
| **Unattended agent runs** | Each run separates a refusal that is the fleet WORKING (nothing delegated, already ran today, mock provider, a budget ceiling doing its job) from a fault an operator must fix (a build that raised, a turn that raised, a turn abandoned at the wall clock), and `run()` declares its own job status from that — `run_job` recorded `ok` for any return value, so a night where every allowlisted agent failed to build left /health green and the reasons in the process log. A fault names the exception CLASS, never its message: the reason reaches `job_outcomes.detail`, which `admin.export` ships. The motor the delegation loop never had: the JOBS registry drove sixteen deterministic jobs and zero agent turns, so every agent action started with a human typing. `sweep()` is deterministic and keyless — it notifies the SPONSOR about delegated work with no worklog note for `QUIET_DAYS`, and is the whole feature on mock. `run()` adds ONE bounded model turn per allowlisted agent per day against its own inbox. Bounds, because nobody is watching: `SKEIN_AGENT_RUNNER` is an ALLOWLIST and is EMPTY by default (a runner that discovered its own fleet would grow one every time somebody delegated to a new name), `SKEIN_AGENT_DAILY_TOKENS` refuses the NEXT run (tokens, not dollars — an unpriced model costs NULL, so a dollar cap binds on nothing exactly where a keyless or subscription deployment needs one), `SKEIN_AGENT_RUN_SECONDS` bounds the wall clock on a daemon thread (a ThreadPoolExecutor joins its workers and would wait out the hang it exists to escape), and `claim_job` keys per (agent, team day). The turn runs under the woken agent's identity via `contextvars.copy_context` — a ContextVar does NOT cross a bare thread, and without it the turn ran as the chat identity, read an empty inbox, and had its writes judged against the wrong authority row. Every write still passes the same gate a chat turn's writes pass | `services/agent_runner.py` · job `agent-run` 05:30 · `GET /api/agents/status` |
| **Artifacts & digest — Work → Reports** | handoffs, readouts, digests and both week rituals archived under `data/artifacts/`, and READ BACK on `/artifacts`: a list plus the selected report rendered as formatted markdown. Every generator wrote a file and a row pointing at it and nothing could open one — `list_artifacts` hands out a server-side path, so the daily digest had no reader at all and the two surfaces with buttons dumped raw markdown into a `<pre>`. The body endpoint takes the caller's viewer and refuses a `private` row with the SAME sentence an absent id gets; it also refuses any stored `path` that does not resolve under `data/artifacts/` — `resolve()` runs before the containment test, so a symlink planted inside the directory is followed to its target and then refused. A row whose file is gone is a 500, not a 404: nothing a caller sent can produce it, and as a 404 it would say "no such artifact" about a row the reader can see listed. The renderer is in-repo (`components/artifact-markdown.tsx`), not a library: the chat's `MarkdownTextPrimitive` reads its text from assistant-ui's message-part context and cannot render a string, and the generators emit one small grammar (headings, bullets nested one level, paragraphs, inline bold and code). It builds React elements and never sets innerHTML — an artifact body quotes rows people wrote, so treating it as markup would make every generator an injection sink. Ritual and readout buttons on Work → Health link here instead of dumping source | `GET /api/artifacts` · `GET /api/artifacts/{id}` · `POST /api/digest` · `/artifacts` page |

## Engagements & portfolio

| Feature | How | Surface |
|---|---|---|
| Engagements | the strike-team unit of work; classes (prototype/incident/migration/…); `kind: delivery\|experiment` — experiments carry a timebox + kill criteria, skip the slip forecast, and auto-draft a lesson at close; closing ANY engagement requires an honest conclusion (achieved/partial/missed/invalidated/unmeasured/stopped) — invalidated-on-time is a success, not a slip | `/api/engagements` · dashboard (close out… button) · intake "accept as experiment" |
| Playbooks | YAML templates → engagement + milestones + tasks + rituals, lessons from the same class surfaced at kickoff. `SKEIN_PLAYBOOKS_DIR` overlays a deployment's own playbooks alongside the stock ones — an overlay file with the same slug wins, so a deployment tailors `incident.yaml` without a fork | `backend/playbooks/*.yaml` · `POST /api/playbooks/instantiate` · chat `/plan` |
| **Playbooks that learn** | instantiate SNAPSHOTS the plan it just created (a JSON artifact bound to the engagement, ids not titles — a renamed task is the same task). Nothing else can reconstruct it: milestones move, tasks are added and deleted, and a cancelled ritual leaves no row at all, so by close the original plan is gone. Closing diffs planned against actual — dates moved, work added, planned work never finished, ceremonies that did not happen — and drafts the lesson as a PROPOSAL. ## Operations

| Feature | How |
|---|---|
| **Team time zone** | `SKEIN_TZ` takes an IANA `Region/City` name, or exactly `UTC`. A bare abbreviation is REFUSED: `ZoneInfo("EST")` resolves happily and is a fixed offset, so a team that writes the abbreviation they say out loud gets rituals an hour late for the eight months of daylight time, with /health reporting green. The scheduler fires in this zone and every human-facing "today" reads `db.today()`; STORAGE is unaffected — `db.now()` stays UTC ISO-8601. Four conversions, one per column shape: `today()` for date columns, `local_midnight_utc()` for UTC timestamp columns, `local_day()` for bucket keys compared against a local key, `local_event_window()` for the naive `events.starts_at`. A bad name or a host with no tzdata degrades to UTC and reports `timezone_error` on /health, distinguishing the two faults; the fallback is `datetime.UTC`, never `ZoneInfo("UTC")`, which is itself a tzdata lookup and would raise inside the handler meant to recover | `config.TZ_NAME` · `db.today()` |
| Migrations | append-only numbered SQL, per-migration `BEGIN IMMEDIATE` transactions, `schema_version` |
| **Tamper-evident provenance** | every `activity` row written since the chain landed (2026-07) carries `seq` + `hash` + `prev_hash`: SHA-256 over its own fields, chained to the row before it. A full walk catches an edited row, a deleted row, a removed head or tail, and a re-rooted chain — each at a known seq — and rows inserted outside the chain, reported by count against the recorded baseline. The link walk alone proves too little, so three marks live outside the rows: a monotonic **high-water** seq (catches truncation), the last verified **anchor** (catches a re-forge), and the pre-chain **unchained baseline** (catches smuggled rows). The in-DB marks alone do not defeat an attacker who reads `services/activity.py` and rewrites `app_settings` too — that case is covered by the **anchor log**: each successful nightly verification appends the verified tip (`<utc> seq=<n> hash=<hex>`) to `backups/activity-anchors.log` and, independently, to the same file on `SKEIN_BACKUP_MIRROR` (append, never copy — a truncated local file must not shorten the mirror's history). The daily findings rule replays every line ever anchored against the ledger as it exists now, so a re-forge or truncation has to contradict a record made on an earlier day. **The remaining limits, stated plainly:** rows newer than the last nightly line are covered only by the in-DB marks until tonight; an attacker who rewrites the local anchor log too is caught only by comparing it against the mirror copy, which is a human step after the finding fires; an attacker who can also write the mirror is not caught at all. Detection, never prevention. Rows outside the chain (pre-chain legacy, or `log_activity`'s lock-timeout fallback) are **adopted** nightly: each gets the tail seq + hash inside one write-locked transaction, a chained `adopt_unchained` receipt names the row ids, and the baseline is lowered, never raised. Adoption attests content from that moment on, not provenance — a chain computed today proves nothing about yesterday — and it is what keeps one busy-ledger fallback from failing every later verification forever. The `ledger_rows_adopted` finding (medium) surfaces each receipt: an adoption that no 'activity chain append failed' warning in the server log explains is the tamper signal. `GET /api/activity/verify` (rate-capped, `?tail=1` resumes from the anchor); `/health` carries `activity_chain`; the nightly 03:30 job adopts, verifies the tail, then advances the anchor; the `activity_chain_broken` rule pays for a full walk daily. `services/activity.py` + `db.activity_hash` |

Everything under `/auth/` and `/settings` is exempt (the callback completes the sign-in the gate starts; Settings is where a key gets pasted), and a personal key passes every mode. The gate replaces the page rather than covering it, but the nav and the two overlays are its siblings: `lib/gated.ts` publishes the gated state so `TaskPeek` and the capture palette stand down (a digest `?task=` link otherwise opened an `aria-modal` dialog on top of the gate) and the nav goes `inert`. The nav asserts that in an effect, never as a rendered prop — `TaskPeek` strips `inert` from every body sibling when it closes, and React does not re-apply an attribute it believes is already set. Admin surfaces (roster, key visibility/kill switch, authority, team theme, context strategy, backup, export) take `AdminUser`: named in `SKEIN_ADMINS`, or in the `SKEIN_OIDC_ADMIN_GROUP` IdP group; with neither set, trusted-header mode falls back to every-key-holder (the scarcity model), the other modes stay locked. Perimeter middleware in `main.py` enforces the mode even on a route that forgets its user dependency |
| Usage accounting | tokens/cycles/latency per thread and model when a real provider is on, plus **estimated cost**: `SKEIN_MODEL_PRICES` (`{"model-id": [usd_per_mtok_in, usd_per_mtok_out]}`, empty by default — a shipped price table goes stale, and a stale price is a wrong number presented as accounting) prices each turn AT WRITE TIME so later price changes never rewrite history; an unpriced model gets cost NULL, honest not zero, and every rollup carries `unpriced_calls` so a sum is never mistaken for a total. **Chat threads link to engagements** (sidebar menu → Link to engagement — pick one or type a name to create-and-link inline, snapping to an existing name instead of erroring; `PATCH /api/chats/{id}` with `engagement_id`, 0 clears) and `GET /api/usage` rolls spend per engagement through that link, with unlinked and pre-link turns in one honest `(unlinked)` bucket.
