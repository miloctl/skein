# Skein — feature reference

Everything shipped, grouped by area. Every feature has a deterministic,
keyless core; rows marked **LLM-upgradable** get better with a model provider
but never require one. All writes flow through `backend/app/services/` from
both write paths (human REST, agent tools) and carry provenance
(`origin`, `created_by`) plus an activity-log entry.

**Navigation (since 2026-07-26):** five top-level destinations — My Day ·
Chat · **Work** (Health `/portfolio` · Browse `/dashboard` · Insights
`/insights`) · **Inbox** (Approvals `/review` · Requests `/intake` · Paste
notes `/ingest`) · **Team** (Agents `/agents` · 1:1s `/people` · Charter
`/charter`). All URLs are unchanged; the groups are tabs. Manager-grade
controls (request triage, exec readout, authority editing, promise
verdicts) sit behind a per-browser "manager controls" toggle so developers
never carry the manager cockpit by default. The toggle is scope control, not
authorization: the endpoints behind it are ordinary `CurrentUser` writes and
stay reachable by anyone who can reach the API — only authority editing requires an
administrator (AdminUser).

| Authority half-life | `autonomous`/`notify` grants expire to a findings nudge after 90 days (reconfirm = re-grant); `forbidden`/`review` never expire. "Nothing in Skein is trusted forever — not decisions, not agents" | `POST /api/agents/authority` · `authority_stale` rule |
| Crews | Durable named groups of people, the membership the visibility tier reads (`docs/VISIBILITY.md`) — removing someone takes away their access to every crew-tier row they did not write. Whoever creates a crew becomes its **steward** — the person who adds and removes members — and a crew can never reach zero stewards from either side (removal and self-demotion both refuse). Editing needs strong identity plus stewardship of that crew, or an administrator named in `SKEIN_ADMINS`. Not the scarcity fallback that makes every key holder an administrator in a default trusted-header deployment — with it, any of them made themselves steward and evicted the one who was there, on a boundary that is about to decide what a person reads. An agent identity cannot join: agents read through the gated tool surface with its own authority matrix. Names fold in Python the way roster names do, so `Café` and `CAFÉ` are one crew, and the four system-actor names are refused. A crew is **deactivated**, never deleted (the roster's word, for the roster's reversible shape) — `crews_of` keeps returning a deactivated crew so rows already scoped to it stay readable, while `assert_writable` refuses new ones. Removal takes the person in the body, not the path: a roster name can hold `/`, which no URL path segment matches | `/settings` Crews card · `GET/POST /api/crews` · `POST /api/crews/{id}/members` · `services/crews.py` |
| Visibility tiers | Every content row carries `private` / `crew` / `workspace` (`004_visibility_tier.sql`, 16 tables). `workspace` is the default and is exactly how every row behaved before the column landed, so the migration changes nothing anyone can see. **`crew` is filtered at read time** — `services/scope.py::visible_filter` returns an AND fragment spliced into each scoped read, and it takes the TABLE, never a column, because four tables carry both their real author column and a `created_by` holding the agent slug (on that one, a private note hides from the person who wrote it). **`private` is not filtered, it is excluded** — no FTS row, no embedding, no context pack, digest, readout, finding, calendar event, admin export row, and no body in `activity.detail` (`scope.detail`, because the ledger is hash-chained and a body written there has no undo). Jobs and egress builders have no viewer — "who is this digest for" has no answer — so they read `scope.WORKSPACE_ONLY` and nothing else. The handoff is generated by a person, so it takes a viewer and narrows the body to the artifact's own tier (`scope.audience`). Reading a scoped row needs STRONG identity: in trusted-header mode a name is whatever the caller typed, so `Viewer` carries the strength in the type rather than leaving the rule at every call site. A refusal is 404, never 403, and the absent row and the unreadable row raise the same sentence (`scope.missing`) — any other wording answers "does #12 exist" for sequential integer ids. Writing a scoped row needs crew membership, checked inside the write's own transaction. Handing one to somebody who cannot read it is refused at the write (`assert_readable_by`, with the author exempted — without that, every private capture that classified as a blocker was refused). Changing one you cannot read is a 404 (`assert_editable`, which lets a machine actor work a crew row because the forge webhook and the review-apply path ARE the mechanism, but never a private one). `scope.UNSCOPED` gives every unscoped table a written reason (pinned by `test_every_unscoped_reason_is_written`) and `scope.CLASSIFIED` maps every scoped one to its author column, and three CI tests walk `sqlite_master` and the service AST: any table in neither map, any id-addressed mutation with no guard, and any read of a scoped table with no viewer, no `WORKSPACE_ONLY` and no written excuse | ⌘K palette · standup card · `VisibilityPicker`/`VisibilityBadge` · `services/scope.py` · `tests/test_visibility_{writes,authz}.py` |
| Per-crew context packs | The team pack plus one section of that crew's own rows — decisions, conventions, open questions, open work. The shared body stays a prefix, so a reader can tell which half the whole roster has. Each crew versions independently (a shared counter would bump every crew whenever any one published), and the crew id is in the artifact filename as well as the row. Reading and publishing both need membership, resolved from the viewer so a self-asserted name is not a door; publishing also needs the crew to be active | `GET /api/context-pack?crew=` · `POST /api/context-pack/publish` · `services/context_pack.py` |
| Identity walls | One name, one identity, asked the same way everywhere. `services/users.py::is_agent` folds in PYTHON (NFKC, strip category Cf, casefold) — sqlite's `lower()` is ASCII-only, so a SQL-folded wall read `SCOÜT` and `scoüt` as different names while `resolve_teammate` read them as one. Agent identities are refused on REST at every door AND at the perimeter, because the perimeter runs before any handler and the file-backed catalog reads never reach `routes/deps.py` at all. The four system-actor names (`system`, `scheduler`, `team`, `forge`) are refused for every kind, at creation, at rename, and at each credential door: the activity feed shows a system actor's rows to EVERY viewer, so holding one walks your own writes past the anti-surveillance rule. `refuse_fold_collision` refuses ANY row that folds onto an existing name, same kind included, so `Scout` the human never lands beside `scout` the agent and a second `SCOUT` agent never lands beside the first — authority and trust key on the exact name, so a fold-variant agent row answers to nobody's kill switch. A roster row that predates a wall is named in the boot log, never auto-renamed: moving a person is `rename_user`, which knows all 47 attribution columns and the private notes DB that SQL cannot reach. Operator config never aborts boot — a name it cannot reserve is a logged error, the way a bad model provider degrades to mock | `services/users.py` · `routes/deps.py` · `main.py` perimeter |
| Rate caps | per-user sliding window on flood-prone writes: capture 30/min (REST, chat, and MCP), ingest 6/min, key requests 3/min — a DoS-annoyance guard, not a security control. A spent cap answers **429** with a `Retry-After` computed from the window, never a bare 400, so a client can tell throttling from a malformed body and knows when to retry. The `write` bucket keys on the (agent, requester) PAIR, so the shared default chat identity is not one team-wide budget | `app/ratelimit.py` |
| Deployment tuning | administrator-set runtime limits held in `app_settings`, overriding the env default and clearing back to it: chat/write/capture caps, the flock member deadline, the model socket timeout, and both thread-pool sizes. Every knob carries an inclusive floor and ceiling (a 0 cap refuses everyone; a 1-thread pool deadlocks), reports whether it is live or needs a restart, and is activity-logged. Cross-knob invariants are refused at write time — the socket timeout can never be set at or below the member deadline, which is the ordering that keeps a cold model load from dying as a failed member. Values are read through per call, never cached, so the numbers stay correct if a second worker ever exists. **Identity settings are deliberately absent** (auth mode, proxy hops, administrators, provider credentials): an administrator who could lower that bar could let themselves through it, so those stay env-only. `AdminUser` for the read too — the remaining headroom is reconnaissance | `GET/POST /api/settings/tuning` · `services/tuning.py` |
| ICS calendar feed | events + milestone/promise due dates; dedicated `SKEIN_ICS_TOKEN` (never the API token); fail-closed when the API is token-locked | `GET /api/calendar.ics` |
| First-run onboarding | checklist computed from real state, personal steps (name, capture, standup, key) separated from team facts (engagement, teammate); dismissible card on My Day (restorable from Settings); anonymous visitors get a single "Who are you?" gate | `GET /api/onboarding` |
| Field guide ("knots") | first-use feature discovery: 31 cards from `backend/fieldguide/knots.yaml`, tied/untied per person, untied cards carry the how-to + deep link; state is SELF-visible only (anti-surveillance rule — no per-person grid, no unlock feed, no activity rows); silent retroactive seeding from existing data; one weekly rotating My Day suggestion (dismiss = permanent); builders' signal is the `feature_unadopted` findings rule (zero-adoption, nameless). Spec + non-negotiables: docs/FIELD-GUIDE.md | `/guide` page · 👤 identity menu (top bar: Settings · Field guide + tied count · identity-strength line — replaces the separate gear button; renaming lives in Settings only) · `GET /api/field-guide` · `/hint` · `POST /api/field-guide/dismiss` (rate-capped) |
| Key self-request | "Request a key" on Settings/1:1s files a team-visible nudge with the exact mint command (idempotent while unread) — the operator ceremony stays, finding the operator doesn't | `POST /api/keys/request` |
| **Activity feed** | Team → Activity: one sentence per provenance-ledger row — "{actor} {verb}" from a registry beside the ledger it names, with an honest generic row for any unregistered action (never a fabricated verb). Salience tracks consequence: destructive and security-relevant actions are loud, writes normal, system bookkeeping quiet. **Scope is the anti-surveillance rule made structural**, enforced in the service: agent and system actors plus your OWN rows — another human's rows never appear and no parameter exists to request them. Raw-rows toggle (same truth, zoom level), click-to-expand per row, seq as the cursor (monotonic and gap-free by construction; pre-036 unchained rows stay on the raw endpoint, which carries the SAME scope — as does My Day's since-yesterday digest, or either would be the one-curl bypass of the rule). A rename never rewrites the ledger: every chained digest covers its actor, so history stays under the old name | `/activity` page · `GET /api/activity/feed` · `services/activity.py::feed` |
| Agent status strip | three states in plain words on Team → Agents: live model, mock ("deterministic mode"), or misconfigured (red dot + the reason from `provider_error`) — plus review-gate state | `GET /api/agents/status` |
| Derived standup "yesterday" | the My Day composer prefills yesterday from the user's own activity log — asked-for input becomes derived | `GET /api/briefing` (`your_work.standup_suggestion`) |
| Themes | 7-pack theme gallery (Loom/Ledger/Phosphor/Atelier/Claw/Hermes/High-contrast) — packs re-weave type, radii, shadows, textures, selvage, and empty-state voice, not just colors; colorway accents + custom two-hue dials (AA at every hue, enforced by `scripts/check_theme_contrast.py` in `lint.sh`: it reads the packs out of `globals.css`, so a new pack is covered on the day it ships, and it holds every colorway thread to 5.5:1 on every pack surface). **`frontend/lib/theme.ts` is the single source** for the pack and colorway ids, the storage keys and the custom-hue formulas: `layout.tsx` GENERATES its pre-paint script from them (`lib/theme-boot.ts`) instead of repeating them, and the contrast checker PARSES them instead of copying them — then fails if `theme.ts` and `globals.css` disagree about which packs exist. Each formula row declares what it must stay legible against, so the sweep covers ink on every pack surface (floor 5.56:1) and solid fills under white text (floor 5.27:1); theme (incl. custom hues) auto-saves to the profile and follows the person to any browser; shareable theme code (copy/paste JSON under Customize & share); operator-set team default adopted by fresh browsers and anonymous visitors (AdminUser, a default never an override) | Settings · `frontend/lib/theme.ts` · `GET/POST /api/users/theme` · `POST /api/users/theme/default` |
| Availability ledger | PTO/on-call/focus windows (absences table): capacity marks people away, the weekly draft skips anyone away 3+ weekdays (listed as skipped, never silently), what-if staffing shows upcoming PTO; manage on Work → Browse Time-away card | `GET/POST/DELETE /api/absences` · tools `add_absence`/`list_absences` (agent create is ALWAYS a proposal) · CLI `skein absences add/list/rm` |
| Delegation work loop | claim → report_progress (worklog) → submit_for_acceptance: acceptance is ALWAYS a proposal bound to the sponsor (others need a reason on record; only key-authenticated sponsor verdicts feed trust); worklog readable pre-verdict | tools `claim_delegated_task`/`report_progress`/`submit_for_acceptance` · `GET /api/tasks/{id}/worklog` · CLI `skein worklog`/`skein inbox` |
| Authority review job | weekly scan turns strong-verdict streaks into FILED proposals: 5 straight key-authenticated sponsor/reviewer approvals at review → propose notify; 3 straight rejections likewise → propose demotion to review (weak-header and override verdicts never count); agents can never approve, so no self-promotion | job `authority-review` · registry entity `authority` |
| Week rituals | Monday brief (each person's own promises, stale decisions, questions, due tasks → personal notification + artifact) and Friday close-out (due promises, stuck-closing engagements, stale proposals, open questions → team notification + artifact); scheduler-run weekly, manual buttons under manager controls on Work → Health | jobs `week-open`/`week-close` · `POST /api/rituals/week-open|week-close` |
| Artifacts & digest | handoffs, readouts, digests archived under `data/artifacts/` | `GET /api/artifacts` · `POST /api/digest` |

## Agents as teammates

| Feature | How |
|---|---|
| Chief-of-Staff chat | streaming SSE; freeform text goes to the agent (`mock` = keyless smart-capture; `ollama` free via local daemon or Ollama Cloud; `openai_compatible` for any OpenAI-shaped endpoint — vLLM, LM Studio, OpenRouter, Groq, Azure; `bedrock` via the ambient AWS chain; anthropic/openai paid) |
| Slash commands | `/plan`, `/briefing`, `/search`, `/remember`, `/playbooks`, `/personas`, `/flocks`, `/help` run deterministically for EVERY provider (`/as` and `/flock` resolve their persona or flock deterministically, then hand off to the agent; both are refused in Slack, which never reaches the route that resolves them) (`app/agents/commands.py` — no model call, no tokens; on live providers the exchange is bridged into the thread's model session via `app/agents/session_log.py` so agent follow-ups have the context); composer autocomplete driven by `GET /api/chat/commands` (type `/h`, ↵ runs, tab completes); unknown `/cmd` gets a did-you-mean instead of a model trip |
| **Long-chat memory** | selectable per deployment: `SKEIN_CONTEXT_STRATEGY=sliding` (default — drop the oldest messages, free) or `summarize` (condense them, costs one extra model call when it fires). `SKEIN_CONTEXT_PIN_FIRST=N` asks the SDK to hold the opening N messages — **but only within a turn.** Skein's chats are database-backed sessions (`agents/session_store.py`), and session restore replays from `offset=removed_message_count`, which skips exactly those leading messages; the pin does not survive a turn boundary. Treat the knob as inert until that changes. Nothing currently keeps the top of a long chat alive across turns. `SKEIN_CONTEXT_PROACTIVE=1` compresses before an overflow instead of after — the threshold is 70% of the MODEL's token context window, not of `SKEIN_CONTEXT_WINDOW`, and Skein sets no `context_window_limit`, so the SDK assumes 200k tokens and the knob does nothing on a smaller local model. **Changing the strategy rewrites each thread's stored manager state on its next turn** (Strands validates the manager class name on restore and would otherwise fail every open thread with `Invalid conversation manager state.`). The replay offset is carried, aligned back to a user turn, so the restored history stays the size the outgoing manager held and never begins with an assistant message. Leaving `summarize` drops the summary text; the messages it stood for stay out of the replay. That loss is deliberate — resetting the offset instead replays a whole thread into the next model call, which overflows, and the recovery overflows again, failing several turns in a row. **The summarizer's own tokens are NOT in `usage_log`**: the SDK calls the model outside the agent's metrics, so `/api/usage` under-reports a summarize deployment. The summarizer runs with no tools and its own hardened prompt, because its output is re-inserted as a `user` message and persisted — the one place pasted third-party text can be laundered into something resembling a standing instruction. Real providers only: mock builds no Strands agent, so the strip shows no strategy rather than claiming one. A bad value degrades to sliding and surfaces `context_error` — the same discipline as `MODEL_PROVIDER_ERROR`, never a failed import. **Settings → Long chats (team)** switches it without a redeploy (AdminUser — it changes what every chat costs); the stored choice overrides the env value, clearing it returns to the env value, and a stored value that stops being valid falls back rather than selecting something else | `_conversation_manager()` · `services/settings.py` · `GET/POST /api/settings/context-strategy` · `GET /api/agents/status` · `/health` |
| **Turn guard** | a chat turn that answers a capture-prefixed message (`todo:`, `q:`, `decision:`, `promised:`, `blocked:`, `req:`) and writes NOTHING says so, as a receipt in the same stream: "Nothing was filed". Prefix match only — the content heuristics in `capture.PATTERNS` treat any message ending in "?" as a question, and a guard that nags on every question mark gets ignored. Any receipt at all (including `refused`/`failed`) silences it: those already stated the truth, and only total silence is the gap. Keyless and model-free. `SKEIN_TURN_GUARD=1` additionally spends ONE model round trip giving the agent a chance to file it (off by default, never on mock, budget of exactly one) | `app/agents/turn_guard.py` |
| Chat history + folders | Sidebar on /chat: every conversation is saved (provider-agnostic transcript in `chat_threads`/`chat_messages`, written by the chat route — works keyless), auto-titled from the first message, rename/move-to-folder/delete per thread, folders are first-class (create empty via 📁+, drag chats in/out, delete unfiles); switching chats rehydrates the transcript; deleting removes transcript AND model-side sessions (rows and pre-045 leftover files); threads are owner-scoped by trusted-network identity (not private — fb:-grade content belongs in ⌘K/People, and the route refuses it); transcripts live in platform.db, so daily backups retain deleted chats up to 14/30 days; JSON export excludes chat tables |
| The bench (personas) | 10 curated specialist personas (`backend/personas/*.md`, incl. career-growth: growth-mentor, training-designer; `SKEIN_PERSONAS_DIR` overlays a deployment's own — same-slug overlay wins, overlay `pack.json` merges field-by-field with JSON `null` to clear a stock default) — `/as <persona> <message>` in chat, `/personas` lists them, bench cards on /agents deep-link with a prefilled composer. Same review gate; each persona is its own agent identity (contextvar-threaded), earning separate authority rows and trust scores. Frontmatter can add **behavior fields**: `model` (model ID override, never the provider — a persona file cannot redirect traffic), `temperature`, and `tools` (comma list; deny-by-omission once declared — the persona's Agent is built with exactly those tools, so the model never sees the rest; extra/MCP tools cannot be allowlisted by name). Pack-wide defaults in `personas/pack.json` (`{"defaults": {...}}`), persona wins field-by-field. Runtime parsing is lenient (a malformed file drops off the bench, chat stays up); `python -m app.services.personas` is the strict validator lint.sh and CI run, so the same file fails the build instead of silently vanishing. Works keyless (mock masthead + deterministic routing; behavior fields apply on real providers only). Spec: docs/PERSONAS.md |
| **Flocks** | named groups of 2-4 bench personas called with ONE message: `/flock <flock> <message>` fans out, every member answers under its own masthead in declared order, and a flock with `synthesis: true` adds one merge call that has no tools and writes nothing. ## Context pack (org-brain)

Versioned markdown pack: team roster, engagement health, standing decisions
(with stale warnings), paid-for lessons, conventions, open questions, and how
to plug in. Version bumps only when content changes (hash-deduped); refreshed
daily at 05:00 UTC and written to `data/artifacts/context-pack/`.

- `GET /api/context-pack` · `POST /api/context-pack/publish`
- MCP resource `skein://context-pack` + tool `get_context_pack`
- CLI: `skein context` or `skein context --write AGENTS.md` — Skein
  becomes the context supplier to every other agent the team uses.
- Per-engagement packs: `GET /api/context-pack?engagement=<id>` — a scoped
  subset (outcome, experiment frame, milestones, open tasks + waits, linked
  blockers, class lessons, standing decisions) for delegated agents: cheaper
  tokens, less noise, cleaner blast radius. Generated on demand, unversioned.

## Operations

| Feature | How |
|---|---|
| Migrations | append-only numbered SQL, per-migration `BEGIN IMMEDIATE` transactions, `schema_version` |
| **Tamper-evident provenance** | every `activity` row written since migration 036 carries `seq` + `hash` + `prev_hash`: SHA-256 over its own fields, chained to the row before it. A full walk catches an edited row, a deleted row, a removed head or tail, and a re-rooted chain — each at a known seq — and rows inserted outside the chain, reported by count against the recorded baseline. The link walk alone proves too little, so three marks live outside the rows: a monotonic **high-water** seq (catches truncation), the last verified **anchor** (catches a re-forge), and the pre-036 **unchained baseline** (catches smuggled rows). The in-DB marks alone do not defeat an attacker who reads `services/activity.py` and rewrites `app_settings` too — that case is covered by the **anchor log**: each successful nightly verification appends the verified tip (`<utc> seq=<n> hash=<hex>`) to `backups/activity-anchors.log` and, independently, to the same file on `SKEIN_BACKUP_MIRROR` (append, never copy — a truncated local file must not shorten the mirror's history). The daily findings rule replays every line ever anchored against the ledger as it exists now, so a re-forge or truncation has to contradict a record made on an earlier day. **The remaining limits, stated plainly:** rows newer than the last nightly line are covered only by the in-DB marks until tonight; an attacker who rewrites the local anchor log too is caught only by comparing it against the mirror copy, which is a human step after the finding fires; an attacker who can also write the mirror is not caught at all. Detection, never prevention. Rows outside the chain (pre-036 legacy, or `log_activity`'s lock-timeout fallback) are **adopted** nightly: each gets the tail seq + hash inside one write-locked transaction, a chained `adopt_unchained` receipt names the row ids, and the baseline is lowered, never raised. Adoption attests content from that moment on, not provenance — a chain computed today proves nothing about yesterday — and it is what keeps one busy-ledger fallback from failing every later verification forever. The `ledger_rows_adopted` finding (medium) surfaces each receipt: an adoption that no 'activity chain append failed' warning in the server log explains is the tamper signal. `GET /api/activity/verify` (rate-capped, `?tail=1` resumes from the anchor); `/health` carries `activity_chain`; the nightly 03:30 job adopts, verifies the tail, then advances the anchor; the `activity_chain_broken` rule pays for a full walk daily. `services/activity.py` + `db.activity_hash` |
| Scheduler (UTC) | one `JOBS` registry (`services/jobs.py`) drives cron + startup catch-ups: hourly blocker sweep · 03:00 backup · 03:30 activity-chain verify · 05:00 context pack · 05:15 forecast snapshot · 06:00 Mon weekly plan · 06:15 Mon stale-WIP nudge · 06:30 Mon week-open brief · 06:45 Mon authority review · 15:00 Fri week-close · 06:30 stale decisions · 06:50 findings · 07:00 digest · 07:05/15:05 notification flush · monthly retention prune (1st, 04:00) — all idempotent via `claim_job` CAS or status flips; every run records status/duration to `job_outcomes`; `/health` reports last success + stale flag per job |
| Backups & export | atomic daily SQLite backups (keep 14) + JSON export, `SKEIN_BACKUP_DIR` to relocate, `SKEIN_BACKUP_MIRROR` copies each backup off-box (keep 30) — point it at a mounted NAS path |
| CI | Gitea Actions (`.gitea/workflows/ci.yml`): the full lint gate + pytest + frontend build per push; register a runner repo-level (docker mode). Keep a runner that shares a host with a live deployment push-only |
| Docker | multi-stage frontend image, slim non-root backend image, healthchecks, single `SKEIN_HOST` knob, named `skein-data` volume |
| Auth model | `SKEIN_AUTH_MODE` picks the door, `routes/deps.py` is the single branch point: `trusted-header` (default — self-asserted `X-User` name picker, trusted network / local dev; optional `SKEIN_API_TOKEN` shared bearer; boot warns) · `api-key` (every request needs a personal `sk-skein-…` key) · `oidc` (IdP-issued JWTs validated in-process in `app/oidc.py` — JWKS via issuer discovery or `SKEIN_OIDC_JWKS_URL`, asymmetric algorithms only, then iss/aud/exp; keys still work for automation). An unknown mode fails CLOSED (503 on every `/api` request, `/health` says why, and the rejected value goes to the log rather than the body). Token validation is hardened against the fact that a `kid` is attacker-chosen and read BEFORE any signature check: fetches carry a 5s timeout, an unknown-kid JWKS refresh is throttled to one per minute, a failed discovery is remembered for 30s, and the middleware runs all of it off the event loop — otherwise a stream of forged kids freezes the server and floods the IdP. In the locked modes `/docs`, `/redoc` and `/openapi.json` are closed too, since they sit outside `/api` where the perimeter cannot see them. **Browser sign-in** is authorization code + PKCE (S256 only): `GET /api/auth/config` tells the web app which identity model the deployment uses — so the self-asserted name picker only ever appears in trusted-header mode — and `POST /api/auth/token` relays the code to the IdP. The relay means the identity provider needs no CORS grant for the app's origin, and the token is validated here before the browser is told the sign-in worked. Both routes are pre-credential by nature and rate-capped by client address — behind a reverse proxy, set `SKEIN_TRUST_PROXY_HOPS` to the proxy depth (OpenShift router = 1) so the cap reads the forwarded client instead of sharing one bucket across the deployment; at the default 0 the header is ignored, because trusting it on a direct connection lets a caller pick their own bucket. `SKEIN_OIDC_CLIENT_ID` registers as a **public client**: there is no client-secret setting anywhere, which is the point of PKCE. Access tokens refresh silently one minute before expiry, single-flighted so a page firing six requests sends one refresh. Sign-out is local — the IdP session is untouched (RP-initiated logout is a recorded follow-on). Admin surfaces (roster, key visibility/kill switch, authority, team theme, context strategy, backup, export) take `AdminUser`: named in `SKEIN_ADMINS`, or in the `SKEIN_OIDC_ADMIN_GROUP` IdP group; with neither set, trusted-header mode falls back to every-key-holder (the scarcity model), the other modes stay locked. Perimeter middleware in `main.py` enforces the mode even on a route that forgets its user dependency |
| Usage accounting | tokens/cycles/latency per thread and model when a real provider is on, plus **estimated cost**: `SKEIN_MODEL_PRICES` (`{"model-id": [usd_per_mtok_in, usd_per_mtok_out]}`, empty by default — a shipped price table goes stale, and a stale price is a wrong number presented as accounting) prices each turn AT WRITE TIME so later price changes never rewrite history; an unpriced model gets cost NULL, honest not zero, and every rollup carries `unpriced_calls` so a sum is never mistaken for a total. **Chat threads link to engagements** (sidebar menu → Link to engagement — pick one or type a name to create-and-link inline, snapping to an existing name instead of erroring; `PATCH /api/chats/{id}` with `engagement_id`, 0 clears) and `GET /api/usage` rolls spend per engagement through that link, with unlinked and pre-link turns in one honest `(unlinked)` bucket. `SKEIN_MONTHLY_BUDGET_USD` arms the `budget` findings rule: high when month-to-date estimated spend reaches the ceiling, medium "cannot be measured" when a budget is set but no call is priced — silence there would read as under budget while nothing was counted |
